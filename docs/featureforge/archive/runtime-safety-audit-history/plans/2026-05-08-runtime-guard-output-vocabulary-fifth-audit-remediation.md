## Execution Mode

Sequential implementation. Complete each task in order. After each task, run strict clippy and the full nextest suite with no fail fast before clean-context review. Remediate review findings, re-run verification, and re-review until the task has no identified issues.

## Goal

Eliminate the remaining actionable fifth-audit issues:

- `close-current-task` must not mutate authoritative dispatch lineage before public mutation authorization.
- Workflow text must never emit `--plan none` as an executable-looking command.
- Task-boundary reason-code vocabulary must have one owner.
- Public `next_action` text must have one owner.

## Architecture

The runtime must preserve this flow:

CLI args -> command module -> public mutation guard -> transition/write authority -> event append -> reducer -> read model -> route decision -> workflow operator presentation.

This remediation tightens the command/write boundary and removes remaining public-output and vocabulary drift:

- `close-current-task` will authorize against the initial shared routed status before any dispatch refresh helper can claim write authority.
- Workflow text rerun guidance will become plan-aware; empty plan paths produce non-command guidance.
- Task-boundary reason-code constants and predicates will live behind a shared reason-code owner module.
- Public next-action text must be produced through shared next-action helpers, not re-authored string literals in router/public-route modules.

## Known Footguns / Constraints

- `ensure_current_review_dispatch_id_for_command` is a writer. Any path that can reach it must already have mutation authorization or must be proven read-only.
- Normal stale-dispatch `close-current-task` recovery must keep working. The fix must not regress public close owning dispatch refresh.
- `recommended_public_command_argv` is the authoritative exact machine invocation when present; `recommended_command` is display-only compatibility text, and completed template bindings are executable only after concrete inputs are bound.
- Empty plan paths are not executable inputs. Rendering `none` in a command position is a public-output bug.
- Some reason-code literals appear in user-facing error messages. Centralization should target semantic decisioning first; message emission can use constants, but historical archives do not need rewrite.
- Boundary tests should catch future drift without forbidding historical archived docs or intentionally synthetic negative fixtures.

## Ordered Tasks

### Task 1: Authorize `close-current-task` before dispatch refresh

#### Spec Coverage

- Public mutation authorization precedes dispatch refresh in `close-current-task`.
- Out-of-route `close-current-task` cannot mutate event log or transition state.
- Normal stale-dispatch public close still refreshes and records closure after authorization.

#### Goal

Make `close-current-task` fail closed before any write-capable dispatch refresh when it is not the exact public route or explicit repair target.

#### Context

The fifth audit found that `close_current_task` computes routed status early, then calls `ensure_current_review_dispatch_id_for_command` in the no-dispatch-candidate fallback before `require_close_current_task_public_mutation` runs. That helper claims write authority and persists authoritative dispatch state.

#### Constraints

- Preserve idempotent already-current closure behavior.
- Preserve the public stale-dispatch happy path where status/operator route to `close-current-task` without requiring a public dispatch id.
- Do not duplicate eligibility logic locally.
- Do not add a hidden helper or compatibility flag.

#### Done when

- Every write-capable `close-current-task` path has public mutation authorization before the write.
- Dispatch refresh cannot run on an out-of-route public invocation.
- A regression test proves event log/transition state do not change when an out-of-route close attempt would otherwise refresh dispatch.
- Existing stale-dispatch close-current-task shell smoke still passes.

#### Files

- `src/execution/commands/close_current_task.rs`
- `tests/workflow_shell_smoke.rs`
- `tests/runtime_authority_contracts.rs` or `tests/public_replay_churn.rs`

#### Implementation Steps

1. Identify all write-capable calls in `close_current_task`, including dispatch refresh, task-closure lineage refresh, write authority claims, materialization, and lease cleanup.
2. Move or introduce `require_close_current_task_public_mutation(&status, args.task)?` before the no-candidate dispatch refresh branch.
3. Avoid double-check drift by reusing the same early authorization for positive and negative closure branches, or keep later assertions only as defensive checks that cannot be the first guard.
4. Add a focused regression fixture where `close-current-task` is invoked out of route with no current dispatch candidate but enough state to tempt dispatch refresh.
5. Snapshot authoritative state/event-log count before the rejected command and assert no dispatch strategy checkpoint or event-log mutation was written.
6. Re-run the normal stale-dispatch public close test to prove authorized refresh still works.

#### Validation Expectations

- `cargo test --test workflow_shell_smoke public_close_current_task_records_positive_closure_after_stale_dispatch_lineage_without_dispatch_id -- --nocapture`
- New targeted regression test.
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo nextest run --all-targets --all-features --no-fail-fast`

### Task 2: Remove `--plan none` from public workflow text

#### Spec Coverage

- No public workflow text renders `featureforge workflow operator --plan none --json`.
- No-plan workflow output gives one non-command next instruction.

#### Goal

Make workflow text safe when no plan path is known.

#### Context

`render_phase_from_context` and `render_handoff_output` unconditionally call `operator_json_rerun_guidance`. `workflow_json_rerun_command` currently substitutes empty plan paths with `display_or_none`, creating `--plan none`.

#### Constraints

- Preserve current command-shaped guidance when a real plan path exists.
- Preserve JSON schema fields; this is text rendering behavior.
- Do not create a second routing authority for no-plan cases.

#### Done when

- No text output contains `featureforge workflow operator --plan none`.
- Empty plan paths render a non-command instruction that an approved plan path is required before querying operator JSON.
- Tests cover `render_phase` and handoff/no-plan text behavior.

#### Files

- `src/workflow/operator.rs`
- `tests/workflow_runtime.rs` or `tests/workflow_shell_smoke.rs`
- `tests/public_cli_flow_contracts.rs`

#### Implementation Steps

1. Replace `operator_json_rerun_guidance` with a plan-aware function that returns command guidance only when `plan_path.trim()` is non-empty.
2. For empty plan paths, return a non-command sentence such as: `Command execution authority: Approved plan path unavailable; obtain the approved plan path before querying workflow operator JSON.`
3. Ensure the non-command sentence does not include `featureforge workflow operator --plan`.
4. Add tests for no-plan `render_phase` and no-plan handoff text.
5. Add or extend a static public-output test rejecting `--plan none` in active workflow text/goldens.

#### Validation Expectations

- Targeted workflow runtime/shell test for no-plan text.
- `rg -n "workflow operator --plan none|--plan none" src tests skills agents schemas docs README.md RELEASE-NOTES.md`
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo nextest run --all-targets --all-features --no-fail-fast`

### Task 3: Centralize task-boundary reason-code vocabulary

#### Spec Coverage

- Task-boundary reason-code vocabulary has one owner.
- Boundary tests reject duplicated task-boundary reason-code literals in decision modules.

#### Goal

Eliminate duplicated task-boundary reason-code literals from decisioning modules.

#### Context

`closure_diagnostics.rs` owns public task-boundary classification, but decision modules re-author reason-code strings such as `prior_task_current_closure_stale`, `prior_task_review_not_green`, `task_cycle_break_active`, and `task_closure_baseline_repair_candidate`.

#### Constraints

- Do not obscure user-facing error messages.
- Preserve existing reason-code strings in JSON/status output.
- Historical archived docs do not need rewrite.
- Keep predicates cohesive; do not build a generic catch-all string registry.

#### Done when

- Task-boundary reason-code constants and predicates are exported from one module.
- Decision modules call shared predicates/constants rather than matching repeated literals.
- Boundary tests scan active Rust decision modules and fail on duplicated task-boundary reason-code literals outside the owner and explicit allowed message emission sites.

#### Files

- `src/execution/closure_diagnostics.rs`
- `src/execution/current_truth.rs`
- `src/execution/read_model_support.rs`
- `src/execution/repair_target_selection.rs`
- `src/execution/repair_route_decision.rs`
- `src/execution/follow_up.rs`
- `tests/runtime_module_boundaries.rs`

#### Implementation Steps

1. Promote task-boundary reason-code constants in `closure_diagnostics.rs` to named `pub(crate) const` values.
2. Add helper predicates for semantic groupings used by decision modules, for example structural current-closure reason, stale/current-closure reason, baseline repair candidate, cycle break, negative review, and overlay restore.
3. Replace repeated `matches!` string literals in decision modules with shared predicates/constants.
4. Keep message emission using constants where practical so error output remains exactly the same.
5. Add a boundary test that scans active Rust files and rejects task-boundary reason-code literals outside `closure_diagnostics.rs`, explicit test assertions, and documented message-emission allowlist entries.

#### Validation Expectations

- `cargo test --test runtime_module_boundaries -- --nocapture`
- Targeted tests touching task-boundary routing, including public replay and shell smoke as needed.
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo nextest run --all-targets --all-features --no-fail-fast`

### Task 4: Centralize public next-action label ownership

#### Spec Coverage

- Public next-action labels are generated by shared helpers.
- Boundary tests reject raw public next-action string ownership drift.

#### Goal

Ensure public `next_action` text comes from shared next-action vocabulary, not raw route-module string assignments.

#### Context

`public_next_action_text` maps `NextActionDecision` to labels, but `public_route_selection.rs` rewrites `next_action` with raw strings and `router.rs` constructs several route decisions with raw next-action text.

#### Constraints

- Do not weaken typed public argv authority.
- Preserve existing public labels unless a label is already known unsafe.
- Avoid a broad enum rewrite if helper constructors can centralize ownership cleanly.

#### Done when

- Route modules use shared next-action label helpers or shared constants for public label text.
- Public route overrides are expressed as typed route decisions or shared label functions.
- Boundary tests reject raw public next-action strings in router/public-route modules outside the shared owner.

#### Files

- `src/execution/next_action.rs`
- `src/execution/public_route_selection.rs`
- `src/execution/router.rs`
- `tests/runtime_module_boundaries.rs`

#### Implementation Steps

1. Add shared helper functions or constants for public action labels such as close current task, advance late stage, request final review, execution reentry required, continue execution, wait for external review result, run verification, and runtime diagnostic required.
2. Replace raw assignments in `public_route_selection.rs` with the shared helpers/constants.
3. Replace raw public next-action construction in `router.rs` with shared helpers/constants.
4. Add a boundary test that rejects raw label literals in route modules unless they are in an allowlisted test fixture or shared owner module.
5. Confirm existing public route goldens stay stable unless a legitimate label bug is corrected.

#### Validation Expectations

- `cargo test --test runtime_module_boundaries -- --nocapture`
- `cargo test --test runtime_behavior_golden -- --nocapture`
